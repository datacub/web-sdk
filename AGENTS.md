# AGENTS.md

`@datacub/web`: the datacub analytics SDK for browsers. Bun, TypeScript, no runtime dependencies.

- `src/index.ts`: the SDK (init, track, identify, reset, consent, capture, delivery). `src/global.ts` is the script-tag wrapper.
- `src/scrub.ts`: removes personal data before anything leaves the page. `src/flags.ts`, `src/feedback.ts`, `src/insights.ts`: opt-in modules.
- `types/`: generated by the build, committed. `skills/datacub/SKILL.md`: the install guide coding agents follow for customers.

```sh
bun install
bun run lint && bun run typecheck && bun test   # fast checks
bun run test:browser                            # Playwright, Chromium/Firefox/WebKit
bun run build                                   # dist/ and types/, fails over the size budget
```

Rules:
- Don't break the public API or the wire format the ingestion server accepts. Keep the core under its size budget (`scripts/build.ts`).
- Never collect form values, passwords, card numbers, national IDs or tokens, and no fingerprinting. Consent, revoke and Global Privacy Control must keep working.
- A change to SDK output ships as a new version; never republish a version.
- Use conventional commit titles (`fix: …`, `feat: …`, `chore: …`). `fix` and `feat` release automatically: release-please bumps the version and CHANGELOG, merges its own release PR, and the workflow publishes to npm with provenance. `chore` releases nothing. Nothing is published by hand.
